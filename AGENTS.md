# AGENTS.md — working on Vera as an AI agent (Codex, Claude Code, others)

This file is for any AI coding agent working in this repository. Claude Code also loads the same procedures as
skills from `.claude/skills/`; everyone else should read the files listed below. **This is a public repository.**
Never put secrets, tokens, credentials, private data or personal content in code, commits, skills or board text.

## Golden rules

1. **Land through the Loop Lab pipeline onto `bleeding-edge`.** This applies to code, docs and skills alike, and
   never directly onto `main`. `main` and the production instance change only on the owner's explicit go-ahead,
   or under the owner's written release policy
   (`shared-planning/backbone-roadmap/DECISIONS.md` D4: continuous releases, 2026-10-17). Quote which one in the
   release summary. Never push to origin unless the owner asks. Never use `content.edit`: it merges straight into
   `main`.
2. **Commits are authored by the human.** No AI attribution anywhere: no co-author trailers, no "generated by" lines.
3. **Plans, handovers and evidence go ONLY in the shared planning area**,
   `<git-common-dir>/vera-work/shared-planning/<unit>/`. That is `/home/boejaker/Vera/.git/vera-work/shared-planning/`
   on the host, or `$(git rev-parse --git-common-dir)/vera-work/shared-planning/` from a worktree. It lives inside
   `.git`, so it is never committed or pushed. Read `shared-planning/README.md` first. Never write plans into
   `documentation/` (published product docs only), `Notes/`, the repo root, or your own home directory.
4. **Solid tasks live on the Loop Lab board** (`board.*` capabilities). Findings about someone else's area go as a
   comment on the related board item (search first). Claim before you edit.
5. **Status goes on the records your work already writes** (pipeline summaries and reviews, board progress
   comments), at each phase boundary and at least every ~25 minutes. Chat gets one line.
6. **Diagnose against the live instance, but never edit its checkout.** Prod's Redis traces, UI and behaviour are
   ground truth.
7. **Background model work follows the owner's rules:**
   - use the idle queue;
   - CPU-preferred (`prefer_gpu: false`), `job_type: idle_*`;
   - never put GPU work inside a running census;
   - yield via `census.control.set action=yield`.

## Reaching Vera's capabilities

- **MCP:** register the stdio bridge `vera/ide/vera_mcp_bridge.py` with `--caller-kind codex` (Claude uses
  `--caller-kind claude`), so your work is attributed to you. Don't reuse another agent's identity.
- **HTTP**, which works when the bridge doesn't or hides a capability:
  `POST https://<vera-host>:8999/mcp/call` with
  `{"name": "<cap.name>", "arguments": {...}, "caller_kind": "codex", "session_id": "<your session id>"}`.
  Check `GET https://<vera-host>:8999/health` before deciding Vera is down.
- Name yourself consistently: `codex:<session-id>` (board `frm`, worktree claim `owner`).
- Publish how other sessions reach you: `agents.contact.set(agent=codex:<session-id>, session_name=<the handle your
  operator reaches you by>, tool=codex, units=<units>)` at the start, pass `session=` on `board.claim`/`board.comment`,
  and put `Reach: <handle> (codex, codex:<session-id>)` in unit READMEs and handovers you write. To reach another agent,
  read `contacts` from `board.item.get` / `board.context`, or `agents.contact.get(unit=…)` (vera-coordinate §0).

## Landing a change (short form; the full procedure is `improve-vera-sandboxed`)

1. `evolve.pipeline.begin(title, spawn=true, session_id)` creates the branch, worktree, container and pipeline. If
   the pool is full, use the hand-made worktree fallback in `improve-vera-sandboxed/SKILL.md` §4.
2. Edit **only inside the worktree**. Claim a hand-made worktree at once (`evolve.worktree.claim`).
3. Commit **through the host** (`evolve.sandbox.exec where="worktree" …`). Git over the SMB share fails inside
   worktrees.
4. Test where imports resolve to your worktree (lowercase `vera.X` with the worktree on `sys.path`, or inside the
   branch's container). Run the critical tier via `evolve.unittest.run` / `evolve.pipeline.test`.
   A pipeline from `begin` has run no gate: call `evolve.pipeline.test(id)` before promoting.
5. Review your own diff adversarially, record it (`evolve.pipeline.review`), then
   `evolve.pipeline.promote(id, to="bleeding-edge")`. A docs/skills/UI branch passes the gate without `force`.
   Never force past a red or skipped gate.
6. Update the board item and the unit's README. Write a handover if you stop mid-way.

## Standing owner rules (these were in private agent memory; they bind every agent)

- **Censuses.**
  - Never resume a census you did not park. Yield with `census.control.set action=yield`, never a plain pause.
  - A manual yield blocks later census slots until someone resumes it.
  - Releases wait for a census (`census=goal`).
  - Pipeline gates may run beside a census: the test pool's `busy_avoid` keeps shards off the busy nodes.
- **Working hours.** 18:00-01:00 is a working window, not protected time (owner, 2026-10-16). Schedule heavy runs by
  census and night-queue state, not by the clock.
- **Concurrency.**
  - One model-calling test at a time.
  - One subagent at a time (owner, 2026-10-11).
  - Never two loops at once.
- **Tests gate commits.** Gate on pytest's exit code in a guarded script, never `tests; commit`. A timeout is not a
  pass. Never promote without having read a green result for that exact tree.
- **Opt-in is not dead.** Low use does not make a feature dead. Never offer to delete a feature; dead-candidates go to
  the owner with proof (`shared-planning/backbone-roadmap/synthesis/DEAD-CANDIDATES.md`).
- **Plans stay current.** Update the unit's ROADMAP status board and item note the moment an item lands or measures.
  Say which roadmap item a step is, ask before extras, and never ship a deviation silently.
- **Controls never go in display widgets.** Put controls only where the owner names them.
- **Sandboxes.**
  - `evolve.sandbox.down` needs `branch`: without it, it tears down the PRIMARY. Dry-run by branch first.
  - After a spawn, `git reset --hard bleeding-edge` in the worktree: spawns can start from a stale base.
  - `evolve.sandbox.list` can transiently report 0. Retry; never respawn on that alone.
  - Never `git worktree add` from Windows over SMB: use the host exec.
- **The edge mirror (:8981)** has no per-session sandbox: loops share one `/workspace`, so judge build goals on prod.
  Its provenance shows prod's sha.
- **Prod restarts.** Only via `sys.dev.restart(confirm=true)` or a release. Never kill the process. Run the preflight first:
  loops, the GPU gate and the census.
- **Prod venv.** Before installing into `/home/boejaker/langchain`, pin to the gate image's versions: pip otherwise
  upgrades numpy and breaks numba/gruut.
- **Secrets.** Hand credentials to a person by sealing them into `~/.vera-keydrop`, never in plaintext or a transcript.
  No capability may return a stored secret value.
