VFS-02 is the file server. Every share, the name-keyed estate tree (every container and VM filesystem, read-only) and the model repository are served from one container over SMB3, NFS 4.2, and a WireGuard door for devices away from home. Its own timer rebuilds the estate tree every 5 minutes, so new guests appear without anyone pressing Sync.

        store read-only with pruning off, so no node can delete another's models. New
        models are pulled by the store's single writer, an Ollama on VFS-02 that listens only on
        its own loopback, and appear on every node at once. VFS-02 also publishes the store
        read-only for other machines.

        Build or extend the store
        
These already ran for the five Ollama nodes. To add a node: copy its local
          models in (existing blobs are never rewritten), attach the store read-only, point
          OLLAMA_MODELS in its ollama-vera.service at the mount path, then
          restart the container. Gitea? Not for model blobs: keep Gitea for code and its OCI
          registry for images.

Storage ops (ZFS, cpusets, bind mounts) run over root SSH to each
        PVE node; file-fabric ops run over SSH to VFS-02, found by its
        host-store label — map every node to an SSH credential below. Credentials themselves
        are created and managed in Estate → Connections (the canonical
        SSH store); tag a host proxmox and add it there, then it appears in
        these dropdowns. Reserved CPU ranges are managed in the CPU / NUMA view
        (Estate → Proxmox → CPU / NUMA).
