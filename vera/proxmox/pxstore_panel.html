One copy of every model. A central ZFS dataset holds models / images / artifacts; consumer CTs get it as a read-only bind mount (mpN,ro=1 — restart the CT to apply). Workflow for ollama, ollama-a, ollama-b: ① Provision → ② Consolidate each CT (rsyncs its local models in, no downtime) → ③ Attach ro to all three (keep one writer rw if you pull new models from inside a CT) → ④ re-run Consolidate with free source space ticked.
Gitea? Not for model blobs — git (even LFS) is the wrong shape for 50 GB weights. Keep Gitea for code, use this dataset for models, and a Docker registry (Gitea's built-in OCI registry works) for images.
