Interactive priority

Keep the GPU free for you. While a human is active (a chat generation, or a UI activity ping), background LLM work — dream cycles, V8 loop programs, fabric NLP — is demoted off the GPU pool onto CPU nodes, and (optionally) new background runs are held off entirely. Nothing stops; it just yields.
Background loops (V8 / orchestrated) — the model / agent / engine ALL long-horizon loops run on. Set here to steer every program; leave blank to let each loop choose.

Cluster nodes

Routable LLM targets — Ollama nodes, vLLM servers and external API providers. Node admin (enable/disable, priority) lives in the Workers & Ollama tab — this page controls where requests go. Pin any rule to a vLLM server with a vllm:<id> pin (or vllm:*), or to an API provider with a provider:<id> pin / a provider:<id>/<model> model ref (usage + cost recorded in the API pane; falls back to Ollama on failure). The Ollama mimic proxy is a caller here too — its traffic follows the mimic.proxy per-capability rule below.

Role profiles

Subsystems (the researcher and the IDE) register a profile of named roles — thinker / writer / verifier — and resolve every LLM call through it instead of picking nodes themselves. Rows marked declared are the subsystem's code defaults; editing a row saves a user override that wins. GPU: auto = inherit default policy · prefer · deny. Escalate ≥: prompt size (chars) above which the escalation overrides kick in (e.g. jump to GPU).
